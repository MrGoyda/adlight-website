# 🏢 Enterprise Architect (Forms, State & Resilience)

Этот скилл обеспечивает отказоустойчивость интерфейса в критических ERP-системах и сложных каталогах. Система должна выдерживать ошибки сети, сложный ввод данных и изолировать сбои, не обрушая всё приложение.

## 1. Эталонные Формы (Enterprise Forms & Validation)
Строгий запрет на использование `useState` для управления состоянием полей ввода.
- **Zod + React Hook Form (RHF):** Все формы генерировать ТОЛЬКО связкой `react-hook-form` (производительность без ре-рендеров) и `zod` (строгая типизация).
- **Apple Error State:** Ошибки появляются плавно (через `<AnimatePresence>`). Поле получает подсветку `ring-destructive/20` вместо резких рамок.
- **Безопасный сабмит:** В `onSubmit` всегда использовать `useTransition` (React 19), блокируя кнопку на время Server Action с показом элегантного спиннера.

## 2. Изоляция сбоев (Graceful Degradation)
Приложение никогда не должно показывать стандартный экран ошибки Next.js в production.
- **Файлы `error.tsx`:** Для каждого важного сегмента генерировать свой файл `error.tsx`.
- **Дизайн ошибки:** Ошибка выглядит как часть UI (в Glassmorphism-контейнере) с кнопкой "Повторить" (`reset()`).
- **Глобальный отлов (Toasts):** Любая перехваченная ошибка в Server Actions или мутациях вызывает Toast-уведомление (например, `sonner`), с Haptic-откликом.

## 3. Управление сложным клиентом (Zustand over Context)
Для состояний, которые не могут храниться в URL (корзина, конфигуратор):
- **Никакого React Context:** Строгий запрет на создание тяжелых провайдеров для часто меняющихся данных (избегаем "Render Hell").
- **Zustand:** Генерировать легковесные хранилища с помощью `zustand`.
- **Persistence:** Если состояние переживает перезагрузку страницы (корзина), использовать `persist` middleware для сохранения в `localStorage`.

## 4. Устойчивость к сети (Network Resiliency)
Интерфейс должен учитывать потерю соединения у курьеров или менеджеров в полях.
- **Авто-повтор:** При настройке `SWR` или `React Query` всегда указывать политику `retry` (минимум 3 попытки с экспоненциальной задержкой) перед показом ошибки.
- **Оптимистичный UI (Idempotency):** Мгновенное обновление UI при мутациях. Если запрос окончательно падает после retry-попыток, состояние плавно "откатывается" (rollback) с показом Toast: "Нет сети. Изменения не сохранены".
