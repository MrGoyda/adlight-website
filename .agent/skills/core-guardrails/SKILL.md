# 🤖 AI Agent Guardrails ("Ошейник для ИИ")

Ты — ИИ. Твоя природа заставляет тебя лениться, галлюцинировать контекст и упрощать сложные задачи. Этот раздел — твои жесткие ограничения. Соблюдение этих правил критически важно для сохранения целостности кодовой базы ERP-систем. Эти правила применяются **всегда, при каждом запуске**.

## 1. Защита целостности кода и Деструктивный Рефакторинг (Silent Truncation)
ИИ часто ленится писать весь файл целиком и "забывает" вернуть часть старой логики.
- **Zero Deletion Policy:** Запрещено удалять, комментировать или упрощать существующие функции, хуки или импорты в файле, если пользователь явно не попросил "отрефакторить" или "удалить" их.
- **No Placeholders:** НИКОГДА не используй плейсхолдеры вроде `// ... остальной код здесь`. Ты обязан вернуть **весь** рабочий код модифицируемого блока от начала до конца.
- **Сохранение стейта:** Если ты добавляешь новый UI-элемент, весь окружающий код (особенно хуки жизненного цикла) должен остаться нетронутым.

## 2. Амнезия схемы данных (Prisma Hallucinations)
Строгий запрет на "угадывание" полей базы данных.
- **Read Before Write:** Перед написанием Server Action или API-роута, ты ОБЯЗАН прочитать файл `prisma/schema.prisma` (или типы Supabase) для проверяемой модели.
- **Zero `any` Policy:** Запрещено использовать `any`, `as any` или `@ts-ignore` при ошибках Prisma. Если TypeScript ругается на поле, перечитай схему. Не пиши интерфейсы вручную для сущностей, которые уже есть в ORM.

## 3. Иерархия компонентов Next.js (RSC Circular Doom)
Жесткое соблюдение границ серверного и клиентского рендеринга.
- **Запрет обратного импорта:** Никогда не импортировать Server Component (или серверные функции) внутрь файла с директивой `'use client'`.
- **Паттерн слотов (Composition):** Если клиентскому компоненту нужен серверный, передавать его исключительно через пропс `children` или React Node слоты.
- **RSC по умолчанию:** Все новые компоненты — это Server Components. `'use client'` добавлять только на самый нижний уровень (листья).

## 4. Утечка секретов через окружение (Zero Env Leak)
- **Запрет на `NEXT_PUBLIC_` для секретов:** Никогда не использовать и не советовать префикс `NEXT_PUBLIC_` для любых ключей API, токенов баз данных (`SUPABASE_SERVICE_ROLE_KEY`), секретов Stripe или паролей.
- **Изоляция:** Любое обращение к секретам должно происходить исключительно внутри файлов `route.ts`, Server Actions или Server Components.

## 5. Чистота Tailwind (Class De-duplication)
ИИ путается в каскадности Tailwind и пишет взаимоисключающие классы.
- **Использование утилиты `cn`:** Абсолютно все динамические классы должны оборачиваться в утилиту `cn` (clsx + tailwind-merge) для разрешения конфликтов (`className={cn("flex p-4", className)}`).
- **Избегание дублирования:** Перед выводом JSX проверь, нет ли конфликтующих свойств (например, `text-center` и `text-left` одновременно).

## 6. Защита импортов и состояний
- **Alias Strictness:** Всегда использовать абсолютные импорты через алиас `@/` (например, `@/components/ui/button`). Не выдумывай UI-компоненты — сначала проверь `@/components/ui/`.
- **URL-first State:** Если состояние определяет вид страницы (таб, поисковый запрос), используй URL Search Params (через `nuqs` или `useSearchParams`), а не `useState`.
