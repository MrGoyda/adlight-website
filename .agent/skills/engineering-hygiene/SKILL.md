# 🧽 Engineering Hygiene (Инженерная гигиена)

Эти правила защищают архитектуру от превращения в "спагетти-код". ИИ-агент должен писать код так, будто это долгоживущая ERP-система, а не одноразовый скрипт.

## 1. Изоляция по фичам (Colocation Policy)
Запрещено складывать специфичные компоненты в глобальные директории.
- **Глобальный UI (`@/components/ui`):** Сюда попадают ТОЛЬКО переиспользуемые dumb-компоненты (кнопки, инпуты, `GlassLayer`).
- **Локальность (Colocation):** Если компонент нужен только на одной странице, он должен лежать рядом с ней (например, `app/(dashboard)/orders/_components/OrderCard.tsx`).
- **Разделение логики:** Сложная бизнес-логика выносится в кастомные хуки в папку `_hooks` рядом с фичей, а не пишется простыней внутри `page.tsx`.

## 2. Атомарные транзакции (Prisma $transaction)
Строгий запрет на последовательные мутации БД, зависящие друг от друга (чтобы избежать частичного сохранения данных при сбое).
- **Обязательные транзакции:** Если Server Action выполняет больше одной операции записи (например, заказ + списание остатков), они ОБЯЗАНЫ быть обернуты в `prisma.$transaction`.
- **Изоляция:** Внутри транзакции запрещено вызывать внешние API (например, отправку email), чтобы не блокировать базу данных в случае долгого ответа.

## 3. Запрет "Магических строк" (No Magic Values)
Никакого хардкода бизнес-логики в JSX или функциях.
- **Использование Prisma Enums:** Для статусов, ролей и типов использовать только сгенерированные TypeScript-типы из БД (например, `OrderStatus.IN_PROGRESS`).
- **Словарики (Dictionaries):** Для вывода локализованных статусов использовать объекты-мапперы (Record), а не писать `switch-case` прямо в верстке (`const statusMap: Record<OrderStatus, string> = {...}`).

## 4. Логирование и Мониторинг (Production Logging)
Запрет на использование `console.log` и `console.error` в Production-коде.
- **Утилита логгера:** Все ошибки в Server Actions и API должны передаваться в централизованную утилиту (например, `import { logger } from '@/lib/logger'`), подключенную к Sentry или Axiom.
- **Контекст ошибки:** Лог должен содержать не только текст ошибки, но и бизнес-контекст (ID пользователя, переданные параметры) для воспроизведения бага.
