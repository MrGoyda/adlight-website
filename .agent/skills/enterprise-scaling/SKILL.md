# 🛡️ Enterprise Scaling & Refactoring (System Custodian)

Этот скилл переводит ИИ-агента с уровня «Писатель кода» на уровень «Хранитель систем». В сложных ERP-системах и Enterprise-проектах цена ошибки при рефакторинге колоссальна.

## 1. Изоляция бизнес-логики (Pure Functions Policy)
Код должен быть спроектирован так, чтобы переживать смену UI-фреймворков.
- **Запрет на логику в компонентах:** Математические вычисления, сложная фильтрация, парсинг дат и расчет цен СТРОГО запрещены внутри React-компонентов или хуков.
- **Pure TypeScript:** Любая бизнес-логика выносится в чистые `.ts` файлы (например, `src/utils/pricing.ts`). Функции зависят только от аргументов и не имеют сайд-эффектов.

## 2. Безопасный ИИ-рефакторинг (Controlled Blast Radius)
Агент обязан минимизировать радиус поражения при рефакторинге.
- **Scout Rule:** Улучшай только то, к чему прикасаешься. Не трогай соседние функции, если они работают.
- **Итеративность:** Запрещено полностью удалять старый сложный компонент и писать новый с нуля в один шаг. Сохраняй старые сигнатуры пропсов.
- **V2 Паттерн:** При радикальном изменении критического компонента, создавать `OrdersTableV2.tsx` рядом с V1. V1 удаляется только после тестирования.

## 3. Эволюция схемы Prisma (Zero Downtime Migrations)
Данные — главный актив.
- **Запрет на переименование/удаление:** При рефакторинге БД ЗАПРЕЩЕНО удалять поля в `schema.prisma`.
- **Паттерн Expand and Contract:**
  1. *Expand:* Добавить новое поле опционально.
  2. *Migrate:* Скопировать данные.
  3. *Update App:* Читать из нового поля.
  4. *Contract:* Удалить старое поле только спустя месяцы.
- **Пометка `@deprecated`:** Вместо удаления устаревших API или полей БД, помечать их JSDoc `/** @deprecated */`.

## 4. Стратегия развертывания (Feature Flags & Dark Launching)
Ни одна крупная фича не "выкатывается" сразу для всех.
- **Feature Flags:** Внедрять новые процессы под флагом окружения (например, `NEXT_PUBLIC_FEATURE_NEW_CART === 'true'`).
- **Скрытый рефакторинг (Dark Launching):** При переписывании логики выполнять обе логики (старую и новую) параллельно, возвращая старую, но логируя расхождения.

## 5. Бизнес-документация (Why, not What)
- **Contextual JSDoc:** Все сложные типы и функции должны иметь JSDoc, объясняющий бизнес-контекст (ПОЧЕМУ это существует, а не ЧТО это делает).
- **Оставляй след:** Любой "хак" (например, для Safari) обязан сопровождаться комментарием с объяснением причин.
