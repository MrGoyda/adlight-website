# ADLight CRM Custodian

## Overview
Этот навык регламентирует процессы расширения, изменения и верификации модулей CRM-системы ADLight. Он гарантирует, что каждый новый функционал спроектирован в рамках единой чистой архитектуры Next.js 15+, сохраняет премиальный визуальный стиль Apple Design System и проходит полную автоматическую проверку перед деплоем.

## Dependencies
*   `apple-design-system` — для проектирования компонентов UI.
*   `backend-architect` — для проектирования серверной части и связей.
*   `clean-architecture` — для декомпозиции и паттернов проектирования.
*   `core-guardrails` — базовые лимиты и правила безопасности.

## Quick Start
Перед модификацией CRM-системы агент должен:
1. Изучить текущую схему `prisma/schema.prisma`.
2. Найти нужную страницу в `app/admin/`.
3. Запустить `npm run dev` для отслеживания изменений.

## Архитектура и стандарты разработки

### 1. База данных и Prisma
*   **Связи сущностей:** Любые связи (например, `Lead` $\rightarrow$ `Client`) должны быть безопасными. По умолчанию использовать опцию `onDelete: SetNull` для предотвращения каскадного удаления важных транзакций или лидов.
*   **Синхронизация:** После любого изменения схемы в `schema.prisma` обязательно выполнить:
    ```bash
    npx prisma db push
    npx prisma generate
    ```
*   **Перезапуск Dev-сервера:** В среде Turbopack изменения типов Prisma могут не подхватываться на лету. В случае ошибок валидации типов перезапустите dev-сервер.

### 2. Серверные действия (Server Actions)
*   **Изоляция:** Все действия с БД должны лежать в файлах `actions.ts` внутри папок соответствующих административных страниц (например, `app/admin/clients/actions.ts`).
*   **Обработка ошибок:** Каждое действие должно возвращать объект `{ success: true, ... }` или `{ error: "Сообщение об ошибке" }`. Использовать блоки `try-catch`:
    ```typescript
    export async function myAction(data: any) {
      try {
        const res = await prisma.myModel.create({ data });
        revalidatePath("/admin/my-route");
        return { success: true, data: res };
      } catch (error) {
        console.error("Action error:", error);
        return { error: "Не удалось выполнить операцию" };
      }
    }
    ```
*   **Инвалидация кэша:** Всегда вызывать `revalidatePath` для путей, данные которых были изменены, чтобы интерфейс мгновенно обновлялся.

### 3. Интерфейс (UI/UX) и Дизайн
*   **Цветовая палитра:** Использовать светлую тему, чистый белый фон (`bg-white`), серо-голубые тона для карточек (`bg-slate-50`) и акцентный оранжевый цвет (`text-orange-600 bg-orange-50/50 border-orange-200/50` или `bg-orange-500 hover:bg-orange-600 text-white`).
*   **Эстетика Apple:** 
    *   Скругления углов: `rounded-2xl` или `rounded-3xl` для панелей и модальных окон.
    *   Тени: Мягкие, размытые тени в стиле Glassmorphism (`shadow-[0_10px_30px_rgba(0,0,0,0.015)]` или `shadow-xl`).
    *   Тактильный отклик (Haptics): Обязательно вызывать функцию `triggerHaptic("light")` на обычные нажатия (клики на табы, открытие окон) и `triggerHaptic("success")` на завершение действий (сохранение форм, закрытие сделок).
*   **Навигация:** Любая новая страница админ-панели должна включать в шапку сквозные кнопки навигации (`Заявки`, `Клиенты`, `Финансы`, `Аналитика`).

## Протокол верификации (Verification Protocol)

Каждая доработка должна быть верифицирована следующим образом:

1.  **Проверка типов и компиляции:**
    Запустить полную сборку проекта:
    ```bash
    npm run build
    ```
    Любые ошибки компиляции TypeScript или Next.js должны быть устранены немедленно.
2.  **Проверка линтера:**
    Убедиться в отсутствии предупреждений и ошибок форматирования кода:
    ```bash
    npm run lint
    ```

## Common Mistakes
*   **Кэширование типов Prisma:** Агент забывает перезапустить dev-сервер после `prisma generate`, что приводит к ложным ошибкам компиляции.
*   **Сломанная навигация:** Добавление новой страницы без обновления навигации на остальных трех дашбордах админки.
*   **Отсутствие haptics:** Создание интерактивных кнопок без вызова `triggerHaptic`.
